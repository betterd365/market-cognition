市面上大多数量化交易教程都有一个通病：教你搭一个给千万级资金、10 人团队用的重型架构——Kafka、Flink、Kubernetes、GPU 推理集群、上百个全节点……你没看错，这些组件在开源社区的「量化交易模板」里比比皆是。

**而个人交易者真正需要的是：一台 VPS + Python + 几个技术指标 + ���格的止损纪律。**

本文基于团队内部完整的可行性分析（458 行），提炼出个人量化交易系统的 MVP 设计方案。核心原则只有一个：**做减法**。

---

## 砍掉什么：70% 的「过度设计」

在开始设计之前，我们先列出 MVP 阶段明确不做的部分——这不是偷懒，而是有意识地避免 scope creep：

| 砍掉的项目 | 原因 |
|-----------|------|
| 1000+ TPS 交易系统 | 个人资金量不需要。币安 API 限频 1200 次/分钟，CCXT 默认足够 |
| 100+ 全节点区块链 | 价格数据通过交易所 API 获取，不需要链上节点 |
| Transformer + LSTM 混合模型 | 加密货币中复杂 DL 模型几乎总是过拟合，技术指标+规则引擎效果相当 |
| 实时 GPU 推理管线 | 策略计算量极小（几个 MA），CPU 绰绰有余 |
| Kubernetes 集群 | 一台 VPS 搞定，K8s 运维成本远大于收益 |
| Flink/Kafka 流处理 | Python asyncio + WebSocket 足够 |
| Web 前端 / 可视化界面 | 日志 + Telegram 通知即可 |
| 移动 App | VPS + SSH 管理 |

砍完之后剩下的，才是真正需要的东西。

## 保留什么：三层精简架构

MVP 架构只有三层，每一层都精确定义了职责：

```
Layer 1: 数据层
  Binance WS Client → SQLite
  （实时行情接收+持久化）

        ↓

Layer 2: 策略引擎
  技术指标计算 → 信号生成 → 风控检查
  （TA-Lib 指标 + 规则引擎 + 止损/仓位管理）

        ↓

Layer 3: 执行层
  CCXT 下单 → 订单状态管理 → Telegram 通知
  （自动执行 + 实时报警）
```

核心依赖只有 6 个库：`ccxt`（交易所接口）、`tulipy`（技术指标）、`httpx`（HTTP 客户端）、`asyncio`（协程）、`sqlite3`（存储）、`loguru`（日志）。全部开源免费。

## 双策略互补：趋势 + 均值回归

单一策略在特定市场环境下总会失效。MVP 采用两个经典策略互补：

**策略一：趋势跟踪（主策略）**

- EMA12 上穿 EMA26 → 开多
- EMA12 下穿 EMA26 → 开空
- RSI(14) > 70 时做多减仓 / < 30 时做空减仓orate

**策略二：均值回归（辅助策略）**

- 价格偏离布林带上轨 → 做空
- 价格偏离布林带下轨 → 做多
- 回归至中轨 → 平仓

趋势跟踪在单边行情中获利，均值回归在震荡市中接棒。震荡市亏的钱，由趋势行情赚回来。

---

## 风控第一，盈利第二

这是整个系统最重要的模块。MVP 定义了六条铁律：

| 规则 | 参数 | 逻辑 |
|------|------|------|
| 硬止损 | 每笔 -5%（BTC -3%） | 触达立即市价平仓 |
| 移动止盈 | 盈利 ≥ 3% 后，回落 1% 止盈 | 保护利润 |
| 单笔仓位 | ≤ 总资金 20% | 分散到 3-5 个品种 |
| 总敞口 | ≤ 总资金 50% | 留足保证金 |
| 每日最大亏损 | -10% 当日停�� | 防止情绪化操作 |
| 日内平仓 | 北京时间 6:00 前全部平仓 | 不留隔夜单 |

**关键设计决策：每笔止损单必须提交到交易所，不要只在本地检查。** 这样即使程序崩溃，止损单仍在。这是整个风控体系的生命线。

品种选择上，MVP 只做 BTC/USDT 和 ETH/USDT 两个主流交易对。山寨币流动性差、操纵严重，MVP 阶段不做。

## 4 周上线路线图

### Week 1：基础设施rifiable

- 注册币安 API（仅开交易权限，**关闭提现**）
- VPS 部署 Docker + Python 环境
- WebSocket 行情接收 + SQLite 入库
- Telegram Bot 通知就绪

**里程碑：** VPS 上能看到实时 K 线数据，Telegram 能收到测试消息。

### Week 2：策略 + 风控

- 趋势跟踪策略编码 + 单元测试
- 均值回归策略编码 + 单元测试
- 风控模块（止损/止盈/仓位）完整实现
- 全链路联调：数据 → 策略 → 风控 → 通知

**里程碑：** 模拟盘模式跑通全流程，信号正确，不下真单。

### Week 3：实盘验证

- API 对接实盘（先 100 U 小额测试）
- 监控运行日志 + 通知调优
- 参数微调

**里程碑：** 小额实盘稳定运行 3 天，无异常。

### Week 4-6：优化扩展

- 简易回测框架 + 多币种支持（BTC + ETH + BNB）
- Grafana 可视化监控 Dashboard
- 策略参数自动化搜索

## 风险清单：知道什么可能出错

**资金安全（最优先级）：**

- API Key 仅开交易权限，**关闭��现**
- IP 白名单限制到 VPS 唯一 IP
- 设置每日交易额上限

**策略风险：**

- 不超 3 个可调参数，防止过拟合
- 趋势跟踪在震荡市中可能连续亏损 → 靠均值回归策略对冲
- 只用低杠杆（2-3x），不碰 5x 以上

**黑天鹅：**

- 闪崩（2021 年 5 月 BTC 单日 -30%）：低杠杆 + 硬止损
- 交易所宕机/拔网线：止损单提交到交易所，不依赖本地程序

|------|------|------|
| 交易平台 | Binance | 流动性最高，API 最成熟 |

| 策略数量 | 2 个 | 趋势 + 均值回归互补 |
| 开发语言 | Python | 开发最快，生态最全 |
| 数据库 | SQLite（MVP） | 零配置，够用 |
| 通知方式 | Telegram | 最即时，Bot API 最简单 |
